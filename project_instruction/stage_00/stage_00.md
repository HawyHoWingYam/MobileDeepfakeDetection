# Stage 00: 基礎設施建設與基線建立

## 📋 **階段總目標**

**學術願景**：建立一個可重現、專注學術創新的實驗環境，為論文發表品質的研究奠定堅實基礎，並建立強力基線模型作為後續創新的對比基準。

**核心原則**：
- **學術導向**：每個決策都以學術貢獻為導向
- **深度理解**：親手實現每個組件，深度掌握技術細節
- **可重現性**：所有實驗結果可在不同環境重現
- **基線建立**：建立強力基線，作為衡量後續複雜設計「淨增益」的標尺

### **任務 0.1：環境配置與依賴管理**

**實現任務**：

**成功標準**：
- 環境配置文件 < 50行，註釋清晰
- conda環境創建成功率 > 95%
- 所有核心功能測試通過

### **任務 0.2：智能數據管理系統**
**學術目標**：設計靈活的數據集管理架構，支持多種學術實驗設計，重點配置CelebDF-v2作為主要訓練數據集

**實現任務**：
- **實現 dataset_config.py**：Python數據集配置類，支持多數據集管理
- **統一數據格式**：256x256標準圖像處理流程
- **路徑配置系統**：JSON配置文件支持多數據集，重點配置CelebDF-v2
- **學術標準劃分**：train/val/test嚴格分離，防止數據洩漏
- **Manifest文件生成**：自動生成CSV格式數據清單，支持MD5校驗
- **數據完整性驗證**：全面的數據格式和完整性檢查

**核心設計理念**：
- 類型安全：使用Python typing確保數據類型正確性
- 配置靈活性：支持K-Fold交叉驗證和跨數據集實驗
- 路徑抽象：智能處理絕對路徑和相對路徑
- 驗證機制：自動檢測數據完整性和格式正確性

### **任務 0.3：學術工具函數庫**
**學術目標**：實現核心的學術評估和可視化工具，支持論文級別的結果展示

**實現任務**：
- **評估指標模組 (metrics.py)**：
  - AUC-ROC, F1-Score, 精確度、召回率
  - 溫度縮放校準評估 (ECE, MCE, Brier Score)
  - Bootstrap置信區間計算和統計顯著性檢驗
  - 多重比較校正 (Bonferroni, FDR)
- **可視化工具模組 (visualization.py)**：
  - 學術級ROC曲線和PR曲線繪製
  - 可靠性圖 (Reliability Diagram)
  - 混淆矩陣和性能對比圖
  - 支援多種期刊格式要求
- **實驗工具模組 (experiment_utils.py)**：
  - 隨機種子設置和實驗可重現性
  - 模型檢查點管理
  - 實驗結果記錄和LaTeX表格格式輸出

**學術嚴謹性要求**：
- 所有指標計算都要提供數學公式註釋
- 統計檢驗要包含p值和效應量
- 可視化要支持多種期刊的格式要求
- 結果保存要支持LaTeX表格格式

### **任務 0.4：強大基線模型建立**
**學術目標**：建立一個簡單但強大的單一模型基線，作為衡量所有後續複雜設計「淨增益」的標尺

**理論依據**：
在探索複雜的SupCon、異構專家等創新技術之前，必須建立一個穩固的基線。這個基線將回答關鍵問題：「我們的複雜設計真的比簡單方法更好嗎？好了多少？」

**實現任務**：
- **EfficientNetV2-B3基線實現**：
  ```python
  # 基線模型配置
  baseline_config = {
      'model': 'EfficientNetV2-B3',
      'loss': 'BCEWithLogitsLoss',
      'optimizer': 'AdamW',
      'lr': 1e-3,
      'epochs': 50,
      'input_size': 256
  }
  ```
- **全數據集基線評估**：在CelebDF-v2上完整訓練和測試
  - 記錄詳細的性能指標：AUC, F1, Precision, Recall
  - 建立性能期望基準：基線AUC應達到0.88-0.92
  - 支援balanced_clean配置以獲得現實性能評估

- **基線分析報告**：
  - 不同數據集配置的性能差異分析
  - 不同偽造方法的檢測能力分析
  - 錯誤案例分析和可視化
  - 計算效率基準：推理速度、記憶體使用

- **基線模型優化**：
  - 數據增強策略優化
  - 學習率調度和超參數調優
  - 確保基線模型達到可能的最佳性能

**基線性能目標**：
- 平均AUC ≥ 0.88（balanced_clean配置）
- F1-Score ≥ 0.85
- 推理速度 < 100ms/image
- 為Stage 01 SupCon方法提供強力對比基準

## 🚨 **風險緩解策略**

### **Risk 0.1: 環境配置失敗**
**風險描述**: 依賴衝突或版本不兼容導致環境建立失敗
**緩解策略**:
- **多版本測試**: 準備Python 3.9/3.10/3.11多版本測試方案
- **依賴降級**: 關鍵依賴出現衝突時的版本降級策略
- **雲端備份**: 雲端開發環境作為最後保障

### **Risk 0.2: 基線模型性能不達標**
**風險描述**: EfficientNetV2-B3基線AUC < 0.88，影響後續對比
**緩解策略**:
- **超參數調優**: 學習率、批次大小、正則化參數系統優化
- **數據增強**: 增強數據多樣性提升模型泛化能力
- **模型替換**: 準備ResNet50、EfficientNet-B0作為備選基線
- **集成基線**: 多模型投票作為更強基線選項

**替代基線方案**:
- **Plan B**: ResNet50 + BCE Loss
- **Plan C**: RegNetY-8GF + BCE Loss
- **Plan D**: Vision Transformer Base + BCE Loss

### **Risk 0.3: 數據管理系統缺陷**
**風險描述**: 數據載入錯誤或格式不兼容導致訓練失敗
**緩解策略**:
- **格式檢測**: 自動檢測和修復常見格式問題
- **備選載入器**: 多種數據載入方式的fallback機制
- **手工驗證**: 關鍵數據集的人工抽檢驗證
- **錯誤恢復**: 數據問題的自動修復和報告機制

### **Risk 0.4: 工具庫功能缺陷**
**風險描述**: 評估工具或可視化工具計算錯誤
**緩解策略**:
- **第三方驗證**: sklearn等成熟庫結果對比驗證
- **單元測試**: 每個工具函數的詳細單元測試
- **邊界測試**: 極端情況和邊界值的測試覆蓋
- **同行評議**: 代碼審查和交叉驗證機制
