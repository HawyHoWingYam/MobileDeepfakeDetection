階段一 (最終自動化版)：詳細執行藍圖

總目標： 開發一個「自記錄」的訓練腳本。此腳本在執行後，不僅能訓練出性能可靠的 MobileNetV4 模型，更能自動生成一個包含所有實驗參數、過程指標和性能圖表的完整報告，為後續研究分析提供堅實、可複現的數據基礎。

第一步：建立自動化實驗框架

本步驟的最終目標： 讓您的 train_stage1.py 腳本在運行啟動的瞬間，就自動為本次實驗創建好一個獨立、乾淨的「數字檔案櫃」，並準備好記錄所有信息的「實驗日誌本」。

1.1 設計實驗產出的檔案結構

要做什麼： 在您的項目根目錄下，手動創建一個名為 outputs 的文件夾，並在其中再創建一個名為 stage1 的子文件夾。這個 outputs/stage1/ 將作為所有第一階段實驗的總存放處。

完成標準： 您的文件系統中存在路徑 /path/to/your/project/outputs/stage1/。

1.2 實現運行目錄的自動創建

要做什麼： 在 train_stage1.py 腳本的邏輯最開始，加入功能：每當腳本運行時，它必須讀取當前的系統日期和時間，並基於此創建一個獨一無二的文件夾名稱（例如 run_20251019_113000）。然後，它會自動在 outputs/stage1/ 目錄下創建這個文件夾。

完成標準： 運行一次腳本後，您能在 outputs/stage1/ 文件夾下看到一個新生成的、帶有時間戳的子文件夾。

1.3 自動初始化日誌記錄器

要做什麼： 腳本必須接著自動初始化一個TensorBoard的日誌記錄器（SummaryWriter）。這個記錄器的日誌輸出路徑，必須精確地指向步驟1.2中剛剛自動創建的那個唯一的運行目錄。

完成標準： 再次運行腳本後，在那個新生成的時間戳文件夾內，您會看到一個新的TensorBoard日誌文件（通常是一個 events.out.tfevents... 文件）。

第二步：數據加載與增強管道 (自動化數據流)

本步驟的最終目標： 建立一條標準化的、從硬盤上的 .csv 文件到模型訓練所需的數據批次（Batches）的自動化流水線。

2.1 創建數據集接口

要做什麼： 創建一個自定義的PyTorch Dataset 類。這個類的唯一職責就是作為數據的接口：它在被創建時讀取 train_manifest.csv 或 val_manifest.csv，並能根據給定的索引號，準確地從硬盤中加載對應的圖像文件及其標籤（0或1）。

完成標準： 您可以實例化這個類，並成功地從中取出任何一個數據點（一張圖像及其標籤）。

2.2 定義數據預處理與增強策略

要做什麼： 設計兩套圖像變換（Transform）序列。

訓練集序列： 這是一套複雜的變換，目的是增加數據的多樣性。它必須包含：隨機的水平翻轉、隨機的色彩抖動（輕微調整亮度、對比度）、以及最終的標準化。

驗證集序列： 這是一套簡單的變換，只包含圖像尺寸調整和標準化，以確保評估時的條件一致。

完成標準： 這兩套變換序列被定義好，並能在步驟2.1的 Dataset 類中被調用，應用於加載的圖像上。

2.3 建立自動化數據供給器

要做什麼： 使用PyTorch的 DataLoader 來包裝您創建的 Dataset 對象和定義好的變換序列。

完成標準： 您能成功創建訓練和驗證兩個 DataLoader 實例。當您從訓練 DataLoader 中迭代取數據時，它能自動、隨機地供給一批（例如32張）經過了數據增強的圖像數據。

第三步：模型初始化

本步驟的最終目標： 準備好一個結構正確、蓄勢待發的 MobileNetV4 模型，等待接收數據進行訓練。

3.1 加載預訓練模型

要做什麼： 使用 timm 庫的功能，根據您在腳本配置中指定的模型名稱，從網上或本地緩存中加載 MobileNetV4 的預訓練權重。

完成標準： 一個預訓練的 MobileNetV4 模型對象成功加載到內存中。

3.2 客製化模型以適應任務

要做什麼： 找到模型原有的、為1000分類設計的分類頭（Classifier），並將其替換為一個新的、只有一個輸出節點的線性層。這個節點將輸出一個數值（logit），用於後續的二元分類判斷。

完成標準： 模型結構的最後一層被成功替換，現在它是一個為您的特定任務量身定制的模型。

第四步：實現全自動日誌記錄的訓練循環

本步驟的最終目標： 打造整個腳本的核心引擎——一個不僅能訓練模型，還能在每一個關鍵節點自動記錄詳細實驗數據的智能循環。

4.1 自動記錄實驗配置

要做什麼： 在訓練循環正式開始前，腳本必須讀取所有您通過命令行傳入的超參數（如學習率、批次大小），並使用 writer.add_hparams() 功能，將這組配置與本次運行的所有結果進行永久性關聯。

完成標準： 在TensorBoard的HParams儀表板中，能看到一次新的運行記錄，其中包含您設定的所有超參數。

4.2 在循環中自動記錄過程指標

要做什麼： 在每一個訓練輪次（epoch）結束，並完成對驗證集的評估後，腳本必須自動執行一連串的記錄動作：

計算並記錄訓練平均損失到 Loss/train。

計算並記錄驗證平均損失到 Loss/validation。

計算並記錄驗證集AUC分數到 Performance/AUC。

計算並記錄驗證集F1分數到 Performance/F1_Score。

計算並記錄驗證集準確率到 Performance/Accuracy。

完成標準： 在TensorBoard的SCALARS儀表板中，您能看到對應上述每一個指標的圖表，並且圖表上有一個新的數據點。

4.3 自動保存性能最佳的模型

要做什麼： 腳本內部必須有一個變量來持續追蹤「歷史最佳驗證集AUC分數」。在每個輪次結束時，腳本會自動將當前的AUC分數與這個歷史最佳值進行比較。如果當前更好，它會自動將當前的模型權重保存（或覆蓋）到本次運行的目錄下，命名為 best_model.pth。

完成標準： 訓練結束後，在該次運行的文件夾中，best_model.pth 文件裡存儲的必然是整個訓練過程中AUC表現最好的那個模型狀態。

第五步：執行實驗與自動圖表生成

本步驟的最終目標： 實際運行一次或多次實驗，並親身體驗從命令行輸入到在瀏覽器中看到交互式圖表的無縫自動化流程。

5.1 執行訓練

要做什麼： 在您的終端中，輸入 python train_stage1.py 命令，並附上您想測試的超參數組合（例如 --lr 0.001 --batch_size 64）。

完成標準： 腳本開始運行，屏幕上打印出訓練進度，同時在後台，所有日誌文件都已被自動創建和持續更新。

5.2 啟動並查看自動生成的圖表

要做什麼： 打開第二個終端，運行 tensorboard --logdir outputs/stage1。然後在瀏覽器中打開其提供的網址。

完成標準： 您能在瀏覽器中看到一個交互式的儀表板。TensorBoard已經自動掃描了您的所有實驗日誌，並為您生成了所有指標的趨勢圖。您無需編寫任何一行繪圖代碼。

第六步：分析自動生成的結果

本步驟的最終目標： 利用被自動創建的圖表和數據，對所有實驗結果進行科學分析，並選出階段一的最終「冠軍」模型。

6.1 進行視覺化分析

要做什麼： 在TensorBoard中，仔細觀察性能曲線。尋找那些損失平穩下降、驗證集AUC穩步上升且最終達到較高水平的實驗。同時，注意訓練損失和驗證損失之間的差距，差距過大意味著過擬合。

完成標準： 您能夠根據圖表，定性地判斷出哪些實驗運行得比較好，哪些比較差。

6.2 進行量化比較與最終決策

要做什麼： 切換到TensorBoard的HParams儀表板。這個界面會將所有實驗的超參數和它們最終達到的最佳性能指標整理成一個表格。您可以直接對「最高AUC」這一列進行排序。

完成標準： 您根據這個表格，結合視覺化分析，最終確定了綜合表現最好的那一次運行。其對應的運行目錄下的 best_model.pth 文件，就是您階段一的最終、也是最完美的產出。
