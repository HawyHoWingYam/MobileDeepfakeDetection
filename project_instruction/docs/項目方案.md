研究課題：面向移動端防詐騙應用的兩階段級聯 Deepfake 檢測系統研究

---

本文件是項目整體方案的「最終版」說明，已與當前程式碼和論文內容對齊。與早期計畫相比，最大的調整是：

- 預設系統為「兩階段級聯」：Stage~1 MobileNetV4 輕量過濾器 + Stage~2 EfficientNetV2-B3 精準分析器。  
- Stage~3 LightGBM 元模型與 GenConViT 混合架構只作為研究性探索，不作為最終部署路徑。  
- 級聯策略採用「全域閾值 + 系統級指標」的離線調優，而不是每支影片動態調整閾值。  
- 手機端目前採用 TorchScript + 動態量化 (PTQ)，QAT + KD 被視為未來擴展方向。

以下從背景、技術路徑、數據與評估、進度與貢獻四個角度總結整個項目。

---

## 1. 研究背景與問題定義

生成式 AI 技術使基於深度學習的影像與影片偽造（Deepfake）極易獲得，其中以面部替換（Face Swap）最常被用於詐騙與虛假資訊。傳統深度偵測模型多針對伺服器或高性能 GPU 設計，直接搬到移動端（手機）時會面臨：

- 模型過大、延遲過高，無法在日常設備上實時或準實時運行；  
- 單一閾值下，難以同時兼顧「低假陰性（高召回）」與「低計算成本」；  
- 對真實世界 in-the-wild 數據（壓縮、噪點、模糊、多來源平台）泛化差。

本研究的核心問題是：  
**如何在資源受限的移動設備上，構建一個既具有高召回能力，又能顯式控制計算成本與風險指標的 Deepfake 檢測系統？**

---

## 2. 核心技術路徑

### 2.1 系統總覽：六階段管線與兩階段級聯

整體管線分為六個階段（與論文 Method 一致）：

1. **Stage~1：輕量快速過濾器** —— MobileNetV4-Hybrid-Medium，對每一張人臉圖像給出偽造機率。  
2. **Stage~2：精準專家模型** —— EfficientNetV2-B3，專注於 Stage~1 無法確定的「困難樣本」。  
3. **Stage~3（可選）：LightGBM 元模型** —— 對多個專家特徵做堆疊融合，作為研究性工具。  
4. **Stage~4：級聯閾值調優** —— 離線網格搜尋 $(\tau_{\mathrm{low}},\tau_{\mathrm{high}})$，在給定 Stage~2 使用率預算下最小化 FNR。  
5. **Stage~5：跨資料集與擾動魯棒性評估** —— 包含 Deepfake-Eval-2024 OOD 評估與 JPEG/噪點/模糊等干擾測試。  
6. **Stage~6：移動端導出** —— 將模型導出為 TorchScript，配合動態量化 (PTQ) 與閾值/溫度設定，封裝成可在手機上使用的推理 bundle。

**預設部署系統只使用 Stage~1 + Stage~2 + Stage~4 + Stage~6 四個部分**，Stage~3 和 GenConViT 只在研究與附錄中出現。

---

### 2.2 Stage~1：MobileNetV4 輕量級過濾器

- Backbone：MobileNetV4-Hybrid-Medium（timm），輸入解析度統一為 $256\times256$ RGB。  
- 任務：對單張人臉圖像進行二分類（real / fake），作為級聯的第一道篩檢。  
- 訓練策略：
  - 以多資料集聯合訓練（CelebDF-v2, FaceForensics++, DFDC, DeeperForensics-1.0）的平衡 manifest 為基礎；  
  - 使用輕量增強（水平翻轉、顏色抖動、仿射變換、Gaussian blur），優先確保穩定性；  
  - Optimizer 採用 AdamW，學習率 Cosine 衰減，早停依據 validation AUC；  
  - 訓練完成後，額外在驗證集上做溫度縮放 (Temperature Scaling) 校準機率。

Stage~1 的設計目標是：在極低計算成本下，**以盡可能低的洩漏率（Stage 1 Leakage）快速淘汰明顯的真實樣本與部分偽造樣本**。

---

### 2.3 Stage~2：EfficientNetV2-B3 精準專家 + Hard Example Mining

- Backbone：EfficientNetV2-B3，輸入解析度同樣為 $256\times256$。  
- 訓練資料：與 Stage~1 相同的聯合 manifest，並在部分實驗中加入「困難樣本子集」以強化邊界學習。  
- Hard Example Mining：
  - 利用 Stage~1 分數定義「模糊區間」與錯分樣本，構建困難樣本 manifest；  
  - 在 Stage~2 訓練中提高這些樣本的出現頻率，提升對難例與邊界樣本的識別能力。
- 校準：同樣對 Stage~2 logits 做溫度縮放，以獲得可解釋的 calibrated probability。

Stage~2 不直接部署在所有樣本上，而是只在「被級聯策略標記為不確定」的樣本上啟動，作為高成本、高精度的專家。

---

### 2.4 Stage~3：LightGBM 元模型與 GenConViT（研究性組件）

早期計畫中曾設計「EfficientNetV2-B3 + GenConViT + LightGBM stacking」作為核心方案。  
實驗結果顯示：

- GenConViT 在本專案設定下，平均表現略低於 EfficientNetV2-B3，且訓練不穩定、耗時顯著增加；  
- LightGBM 元模型在多數折數上 **並沒有穩定優於最佳單一專家**，整體 AUC/F1 甚至略低。  

因此，最終系統：

- **不把 Stage~3 與 GenConViT 納入預設部署路徑**；  
- 只在論文的附錄與 Ablation 裡保留對它們的分析，以展示探索過的替代架構和教訓。

---

### 2.5 級聯閾值調優與系統級指標（Stage~4）

級聯策略採用兩個全域閾值 $(\tau_{\mathrm{low}},\tau_{\mathrm{high}})$：

- 若 $p_1(x) < \tau_{\mathrm{low}}$ → 判為 real，直接返回；  
- 若 $p_1(x) > \tau_{\mathrm{high}}$ → 判為 fake，直接返回；  
- 否則 → 升級到 Stage~2 專家處理。

在 combined validation 上，我們透過 grid search 對 $(\tau_{\mathrm{low}},\tau_{\mathrm{high}})$ 做離線搜尋，以以下指標為主：

- **FNR（False Negative Rate）** —— 儘量降低，以減少漏報偽造；  
- **Stage~2 escalation rate $\pi_2$** —— 表示有多少樣本需要跑專家模型，是計算成本與耗電的關鍵；  
- **Stage~1 leakage rate $\pi_{\mathrm{leak}}$** —— 表示本應為 fake 的樣本被 Stage~1 錯誤放行的比例。

透過這套系統級指標，我們可以選擇例如「FNR < 0.6\% 且 Stage~2 使用率約 1–1.5\%」等操作點，對應不同的部署場景（安全優先 / 手機端優先）。

> 與早期計畫不同，目前實作 **不使用 per-video 動態閾值**，而是使用全域閾值搭配明確的系統級 trade-off 曲線，實作和分析都更簡潔可控。

---

### 2.6 移動端部署與優化（Stage~6）

當前實作聚焦於「可落地、易維護」的 export pipeline：

- 導出：Stage~1/2 轉為 TorchScript 模型，配合 JSON/metadata 保存 $(\tau_{\mathrm{low}},\tau_{\mathrm{high}})$ 與溫度參數。  
- 壓縮：使用 PyTorch 的 post-training dynamic quantization (PTQ) 對線性層做 INT8 量化，將 Stage~1/2 模型尺寸約縮減 70\% 以上，同時保持接近的 AUC。  
- 手機端：目前以「單圖像推理 + 簡單級聯邏輯」為目標設計，詳細手機 SoC 測試與耗電量測尚待後續實驗。

早期計劃中的「QAT + KD」路線被保留為**未來工作**：當需要進一步壓縮 Stage~2 但保持精度時，可考慮以未量化模型為教師，結合 QAT 訓練更輕量的學生模型。

---

## 3. 數據集與評估體系

### 3.1 訓練與驗證數據集

最終實驗使用四個主要影像/影片數據集作為訓練與驗證來源：

- **CelebDF-v2** —— 高品質名人換臉影片；  
- **FaceForensics++ (FF++)** —— 多種經典偽造技術（Deepfakes, Face2Face, FaceSwap, NeuralTextures 等）；  
- **DFDC** —— 多來源、多壓縮、雜訊較重的眾包數據集；  
- **DeeperForensics-1.0** —— 強調真實世界擾動與材質挑戰。

訓練與驗證使用經過統一預處理（MTCNN 人臉擷取、256×256 PNG）的 manifest；  
**DF40 數據集只用於分析「DF40 風格 256×256 圖像」的規格，作為其他影像預處理的參考，不直接參與最終訓練。**

### 3.2 OOD 評估：Deepfake-Eval-2024

- **Deepfake-Eval-2024** 作為 in-the-wild OOD 測試基準，用於評估模型在真實社交平台影片上的表現。  
- 我們在該資料集上同時報告：
  - Calibrated 兩階段級聯的表現；  
  - Stage~2-only 的「上界」表現（高召回但高 FPR 與高計算成本）。

結果顯示：相較於 in-distribution validation，Deepfake-Eval-2024 上的 F1 明顯降低、FNR 顯著升高，凸顯 domain shift 問題。

### 3.3 評估指標

評估分三個層次：

1. **模型層級**：AUC, Accuracy, F1, Precision/Recall, FNR/FPR。  
2. **系統層級**：Stage~2 escalation rate $\pi_2$、Stage~1 leakage rate $\pi_{\mathrm{leak}}$、平均推理時間（Stage~1/2）、模型大小。  
3. **魯棒性層級**：不同 JPEG 壓縮、Gaussian noise、motion blur、brightness 等強度下的 F1/FNR 曲線與 $\pi_2$ 變化。

## 4. 項目實施進度（最終狀態）

### ✅ 已完成

- **Stage~0/資料與環境**：資料路徑與預處理管線確立（256×256 PNG，MTCNN 人臉擷取，manifest 制度）；環境為 Python 3.12 + PyTorch 2.1+。  
- **Stage~1**：MobileNetV4 過濾器訓練、校準與評估；相關腳本與文檔已整理到 `src/stage1/` 與 `docs/stage1_user_guide.md`。  
- **Stage~2**：EfficientNetV2-B3 專家模型訓練、hard example mining 策略、溫度縮放校準。  
- **Stage~4**：兩閾值級聯網格搜尋，選出多個代表性 operating points（例如 FNR≈0.006、Stage~2 使用率≈1.16%）。  
- **Stage~5**：Deepfake-Eval-2024 OOD 評估與 JPEG/噪點/模糊等擾動分析。  
- **Stage~6（部分）**：TorchScript 導出與動態量化、桌面 CPU 延遲估計、移動端導出樣板。

### 🔍 已探索但非預設路徑

- GenConViT Stage~2 替代架構與 LightGBM meta-model 堆疊：在本設定下沒有穩定勝過 EfficientNetV2-B3，故只保留在附錄與 ablation 中作為經驗教訓。

### 📌 尚待進一步工作

- 實際手機 SoC（例如 Snapdragon / MediaTek）上的延遲與功耗測量；  
- 若有必要，評估 QAT + KD 的壓縮潛力，重新訓練具有更小 footprint 的學生模型；  
- 在更多 in-the-wild 資料集上驗證泛化與公平性。

---

## 5. 預期貢獻（對論文與專題的對應）

1. **一個可落地的兩階段級聯 Deepfake 檢測系統**：在維持高召回（低 FNR）的前提下，以極低的 Stage~2 使用率實現顯著的計算節省，適合移動端防詐騙場景。  
2. **一套以系統指標為核心的調優方法**：將 Stage~1 洩漏率與 Stage~2 escalation rate 納入設計與報告，讓部署者可以根據風險預算選擇 operating point。  
3. **對混合架構與元模型融合的實證教訓**：透過 GenConViT 與 LightGBM 的負面結果，說明在強基線下 ensemble 不一定帶來實質收益，為未來工作提供參考。  
4. **一個兼顧可重現性與移動部署的整合框架**：從資料預處理、訓練、級聯調優到 TorchScript 導出，均有對應腳本與文檔，方便導師與未來研究者在此基礎上擴展。
