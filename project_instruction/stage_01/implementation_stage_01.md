# Stage 1 Implementation Plan: SupCon快速過濾器

## 📋 **Implementation Overview**

本階段實現基於監督式對比學習的「真實性建模」範式轉換，構建級聯系統的第一道防線。這是AWARE-NET項目的核心理論創新，將檢測範式從「偽造檢測」轉向「真實性建模」。

---

## 🎯 **Core Implementation Tasks**

### **Task 1.1: SupCon損失函數理論與消融研究**

#### **Priority: 小規模消融研究先行**
在大規模實施前，必須先通過小規模實驗驗證SupCon相對BCE基線的優勢：

**小規模實驗設計策略**：
- **數據量**: 1000樣本（500真實 + 500偽造）
- **訓練週期**: 10個epoch快速驗證
- **批次大小**: 32樣本
- **驗證比例**: 20%
- **核心問題**: SupCon是否真的比BCE帶來改進？

#### **SupCon損失核心設計原理**
**理論基礎**：
- 監督式對比學習損失函數基於特徵相似度計算
- 將同類樣本拉近，異類樣本推遠
- 在特徵空間構建「真實性堡壘」，而非簡單的二分類邊界
- L2正規化確保特徵在單位球面上分佈

**實現要點**：
- 溫度參數τ設為0.07（可調整：0.05-0.2範圍）
- 數值穩定性處理避免overflow問題
- 批次內正負樣本對的高效構建
- 詳細的數學公式驗證和理論推導

#### **批次構建策略設計**
**平衡採樣原理**：
- 確保每個批次包含足夠的正負樣本對
- 最小正負樣本數量：每類至少4個樣本
- 隨機採樣策略避免過擬合
- 批次統計監控（正負比例、對數量統計）

**高效實現策略**：
- 按類別預先分組樣本索引
- 動態調整批次組成確保平衡
- 避免重複計算相似度矩陣
- 記憶體優化的正負對構建算法

### **Task 1.2: MobileNetV4架構設計與理論**

#### **輕量化設計原則**
**架構選擇理由**：
- MobileNetV4專門為移動端設計，效率與效果平衡
- 使用預訓練權重加速收斂
- 適合級聯系統第一階段的快速過濾需求
- 支持實時推理的計算要求

**模型架構設計理論**：
- **Backbone**: MobileNetV4-conv-small預訓練模型基礎
- **投影頭**: 用於SupCon特徵提取，映射到256維空間
- **分類頭**: 最終二分類預測，包含dropout正則化
- **特徵正規化**: L2正規化確保特徵在單位球面

**性能目標設定**：
- 推理速度 < 50ms/image
- 記憶體使用 < 2GB
- 參數量 < 10M（移動端友好）
- 準確率保持在合理水平

### **Task 1.3: 溫度縮放校準理論與實現**

#### **概率校準原理**
**校準必要性分析**：
- 深度模型輸出的原始概率往往過度自信
- 溫度縮放可以改善預測概率的可靠性
- 對級聯系統的閾值決策至關重要
- 提高模型輸出的可解釋性

**溫度縮放設計理論**：
- 使用驗證集優化溫度參數T
- 通過LBFGS優化器最小化交叉熵損失
- 支持動態溫度調整機制
- 提供校準前後的概率對比分析

**校準效果評估框架**：
- **期望校準誤差(ECE)**: 目標 < 0.1
- **可靠性圖**: 校準後應接近對角線分佈
- **統計檢驗**: 校準效果的顯著性驗證
- **閾值敏感性**: 不同閾值下的校準穩定性

### **Task 1.4: 保守閾值策略設計理論**

#### **非對稱閾值原理**
**級聯系統需求分析**：
- 第一階段需要高召回率，寧可誤殺不可放過
- 假陰性成本遠高於假陽性成本
- 為後續階段保留足夠的疑似樣本
- 平衡檢測精度與計算效率

**閾值設計策略理論**：
- **保守閾值**: 設置較低的置信度門檻（如0.3-0.4）
- **動態調整**: 基於驗證集ROC曲線確定最優閾值
- **統計分析**: 不同閾值下的假陽性/假陰性率分析
- **魯棒性測試**: 跨數據集閾值穩定性驗證

## 🚨 **Risk Mitigation Strategies**

### **Risk 1.1: SupCon效果不佳或無效**
**風險描述**: 小規模實驗顯示SupCon相比BCE無明顯改進
**緩解策略**:
- **溫度參數調整**: 測試不同溫度值（0.05, 0.07, 0.1, 0.2）尋找最優設置
- **特徵維度變化**: 嘗試不同投影維度（128, 256, 512）優化特徵學習
- **對比學習變體**: 考慮其他對比學習方法（SimCLR, MoCo適配版本）
- **增強基線策略**: 使用focal loss或label smoothing增強BCE基線
**觸發條件**: 1000樣本實驗中SupCon AUC < BCE AUC + 1%

### **Risk 1.2: MobileNetV4性能不達標**
**風險描述**: 推理速度過慢或檢測準確性不足
**緩解策略**:
- **輸入分辨率調整**: 降低輸入尺寸（224→192→160）提升速度
- **模型變體選擇**: 使用更小的MobileNetV4變體或EfficientNet-B0替代
- **量化優化**: 提前應用INT8量化減少計算開銷
- **架構剪枝**: 移除不重要的層或連接降低複雜度
**觸發條件**: 推理速度 > 100ms 或 整體AUC < 0.85

### **Risk 1.3: 溫度縮放校準失效**
**風險描述**: 校準後預測概率可靠性仍然較差
**緩解策略**:
- **Platt校準**: 使用sigmoid函數替代溫度縮放
- **多變量校準**: 實現向量溫度縮放處理多維輸出
- **集成校準**: 結合多種校準方法提升效果
- **分層校準**: 對不同置信度區間使用不同校準策略
**觸發條件**: 校準後ECE > 0.15或可靠性圖嚴重偏離對角線

### **Risk 1.4: 批次構建策略問題**
**風險描述**: 不平衡批次導致SupCon訓練不穩定
**緩解策略**:
- **採樣參數調整**: 增加每批次最小正負樣本數量要求
- **類別權重平衡**: 在損失函數中添加類別平衡權重
- **動態批次調整**: 根據樣本分佈動態調整批次組成
- **梯度累積**: 使用更小批次配合梯度累積穩定訓練
**觸發條件**: 訓練損失劇烈震盪或長期不收斂

### **Risk 1.5: 跨數據集泛化性差**
**風險描述**: 模型在某些數據集上表現良好，但泛化能力不足
**緩解策略**:
- **多數據集聯合訓練**: 混合多個數據集進行訓練
- **領域適應技術**: 使用adversarial training減少數據集偏差
- **數據增強策略**: 增強數據多樣性提升泛化能力
- **集成策略**: 訓練多個模型針對不同數據集特點
**觸發條件**: 某數據集性能相比平均水平下降 > 10%
