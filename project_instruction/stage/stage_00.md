### **任務 0.4：強大基線模型建立**
**學術目標**：建立一個簡單但強大的單一模型基線，作為衡量所有後續複雜設計「淨增益」的標尺

**理論依據**：
在探索複雜的SupCon、異構專家等創新技術之前，必須建立一個穩固的基線。這個基線將回答關鍵問題：「我們的複雜設計真的比簡單方法更好嗎？好了多少？」

**實現任務**：
- [ ] **EfficientNetV2-B3基線實現**：
  ```python
  # 基線模型配置
  baseline_config = {
      'model': 'EfficientNetV2-B3',
      'loss': 'BCEWithLogitsLoss',
      'optimizer': 'AdamW',
      'lr': 1e-3,
      'epochs': 50,
      'input_size': 256
  }
  ```
- [ ] **全數據集基線評估**：在所有目標數據集上完整訓練和測試
  - DF40, FaceForensics++, CelebDF, DFDC
  - 記錄詳細的性能指標：AUC, F1, Precision, Recall
  - 建立性能期望基準：基線AUC應達到0.88-0.92

- [ ] **基線分析報告**：
  - 不同數據集上的性能差異分析
  - 不同偽造方法的檢測能力分析
  - 錯誤案例分析和可視化
  - 計算效率基準：推理速度、記憶體使用

- [ ] **基線模型優化**：
  - 數據增強策略優化
  - 學習率調度和超參數調優
  - 確保基線模型達到可能的最佳性能

**基線性能目標**：
- 平均AUC ≥ 0.90，F1-Score ≥ 0.85
- 推理速度 < 100ms/image
- 在各數據集間的性能方差 < 0.05

### **⛔ 強制停止條件**
遇到以下情況必須立即停止，重新設計：
1. **環境搭建成功率 < 90%**: 說明依賴管理有問題
2. **核心功能測試失敗 > 5%**: 基礎架構不穩定
3. **代碼品質檢查失敗**: 未通過lint, type check, 或單元測試
4. **記憶體洩漏檢測**: 長時間運行後記憶體持續增長
5. **文檔缺失**: 缺少關鍵技術文檔或API說明
6. **基線模型嚴重不達標**: 平均AUC < 0.85，說明基礎實現有問題
7. **跨數據集性能崩潰**: 某數據集AUC < 0.80，存在嚴重適應性問題

### **🔧 迭代優化觸發條件**
遇到以下情況建議迭代優化：
- 環境創建時間 > 10分鐘
- 數據處理速度 < 預期的50%
- 用戶體驗問題（配置複雜、錯誤提示不清楚）
- 跨平台兼容性問題
- 基線性能在期望範圍但不理想（0.85 ≤ AUC < 0.90）
- 某個數據集性能明顯偏低但不至於崩潰
- 推理速度偏慢（50-100ms/image範圍）

### **📋 基線模型風險應對計劃**
**如果基線模型性能不如預期怎麼辦？**

#### **應對策略層次**
1. **輕微不達標** (AUC 0.85-0.89)：
   - 調整數據增強策略
   - 優化學習率調度
   - 增加訓練epochs
   
2. **中度不達標** (AUC 0.80-0.84)：
   - 檢查數據質量和標籤正確性
   - 嘗試不同的預處理方法
   - 調整模型架構（層數、寬度）
   
3. **嚴重不達標** (AUC < 0.80)：
   - 重新檢查數據集和實現
   - 考慮更換基線架構（ResNet50, RegNet等）
   - 全面審查實驗設置

#### **替代基線方案**
- **Plan B**: ResNet50 + BCE Loss
- **Plan C**: RegNetY-8GF + BCE Loss
- **Plan D**: Vision Transformer Base + BCE Loss
